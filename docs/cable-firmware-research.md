## 从机器码到实机应答

| 文件位置 | 指令或数据 | 解释及交叉验证 |
| --- | --- | --- |
| `0x0000 → 0x84B9` | `02 84 B9` 跳转至启动代码，随后有 `75 81 E5` 设置栈指针。其他向量也跳转到保存寄存器现场的代码。 | 指令和向量布局符合 MCS-51 / 8051 内核。分析时须区分代码空间的 MOVC 和外部数据空间的 MOVX，同一地址数值可指向不同对象。 |
| `0x1003–0x100A`，`0x1FCE` | 镜像头依次存放四字节版本和小端 VID/PID。处理代码从代码空间顺序读取 `0x1003–0x1006`，逐字节写入外部数据空间 `0x0340–0x0343`。 | USB 实读恰为 `0C 09 49 06`。这是把版本常量与返回路径对应起来的证据。 |
| `0x1024`、`0x7C71` | 取内部状态字节 `0x48`，调用表分派例程。紧随的表至少含状态 1–8 和 0x16，各有独立处理地址，缺省目标为 `0x1824`。 | 已识别多状态控制逻辑。仅凭编号无法将各分支命名为插入、充电或出图。 |
| `0xB740`、`0xB75C` | 设备及配置描述符模板。设备修订号在模板里为零，实读为 `0x0C49`；配置值模板为 1，实读为 2。 | 说明部分字段在运行时形成。实读配置只有接口 0，类 0x11，接口声明的数据端点数为 0。控制端点 EP0 可用。 |
| `0xB772 / B7B0 / B7EE / B810` | 厂商、产品、序列号和 VESA 帮助链接四个 UTF-16LE 描述符。 | 四份实机应答逐字节命中镜像。代码 `0x1AF9 / 0x1B24 / 0x1DC2` 分别引用厂商、产品、链接。序列号模板为 `0000000000000001`，单一样本不足以当作每根线独有的编号。 |
| `0xB858` | 88 字节 BOS。处理代码在 `0x1E37` 引用其长度字段，随后设置模板起址。 | 实读 88 字节与模板完全相等，含四个能力描述符。Billboard 声明一个模式，SVID `0xFF01`，模式字段 0，配置状态低两位为 3。 |
| `0xB8B0–0xB8EB` | 描述符后另有代码直接读取的常量。例：`0x414D–0x4170` 将 `00 00 01 FF` 从代码空间拷到 `0x2B4F–0x2B52`。 | 小端值 `0xFF010000` 符合包含 DP SVID 的发现响应对象。下一组小端字 `6C002109 / 0000038B / 01050001` 符合身份头、认证状态、产品 VDO 的顺序，解出 VID 2109、PID 0105。此处为有代码引用的协议解释，尚无 CC 线上抓包证实实际发出的载荷。 |

按 USB Billboard 定义，配置字段 3 的含义为模式配置成功。此次没有连接眼镜，该字段仍与固件默认模板相同，因此它对“当前镜片是否亮”没有独立判定力。不能据此排除链路、供电、屏幕时序或手机软件问题。[USB-IF Billboard 类规范](https://www.usb.org/document-library/billboard-device-class-spec-revision-122-and-adopters-agreement) · [usbutils 字段解析](https://github.com/gregkh/usbutils/blob/master/lsusb.c) · [Linux USB-PD 身份对象定义](https://github.com/torvalds/linux/blob/master/include/linux/usb/pd_vdo.h)

## 有哪些配置和调试接口

**镜像内配置。** 可定位版本、USB 字符串、设备身份及备用模式声明。尾部数据表有多处代码引用，最后一个非 FF 的数据字节位于 `0xB8EB`（不计末尾 CRC）。这些字段属于编译进镜像的常量；单靠本样本无从确认哪些字段由售后按板型配置，也未发现面向用户的设置文件或持久化设置 API。更改描述符会改变上报内容，无法据此推断视频路由或充电行为随之改变。

**已验证的运行态诊断接口。** 标准 EP0 请求读出设备、配置和 BOS，VIA 厂商查询读出版本及状态。芯片识别寄存器 0x18 实读 A0；模式寄存器 0xF7 实读 81，最高位表示运行态。固件返回代码、fwupd 对 VL105 的公开实现及本机读数可以相互核对。GUI 中的周期采样始终使用运行态查询。[fwupd 的寄存器和模式解释](https://github.com/fwupd/fwupd/blob/2.1.9/plugins/vli/fu-vli-pd-device.c)

**尚未证实的接口。** 上游维护流程提到 UART-Rx 和 Watch Mode，这只能说明芯片代码考虑了相应模式。此次 USB 枚举未包含 CDC 串口；没有板上焊盘、引脚、电平、波特率或真实串口日志来证明原厂线引出了 UART 控制台。头显镜像中的 PCUI 与 AT 查询属于另一台 USB 设备。本次也未得到可设置分辨率、刷新率、快充档位、LED 或直接捕获 PD 报文的线缆命令。[头显接口研究](usb-panel-research.md) · [升级器及头显固件](firmware-resource-analysis.md)

## 使用诊断上位机

Windows x64 上单独接入一根原厂线，打开 `resources/CV10-Cable-Tool.exe` 并选择“连接线诊断”。进入该页时自动读一次，勾选“每 2 秒刷新”可观察 USB 重枚举前后的读数；设备离线时会记下读取错误。点“导出采样记录”可保存最近 300 条带时间戳的 JSON，包括原始配置和 BOS，便于旧线与新版供体做同条件比较。此工具适用于电脑充当 USB 主机的接法。在手机充当主机的完整链路中观察 PD 协商，需要相应的主机日志或 CC 抓包。

## 2026-11-25 两版固件与华为升级程序的通信对照

分析样本为本线 C9.49.6（SHA-256 `f16057065c4c29d6d86901239371f2a6aab2bcf03c6976505c8f5971fba93e02`）、供体 C9.52.6（`1ebf1217d0dda526f64ed3b15504db409fbdf25bc866f0fbebb874adcd00485a`）和资料包 04 华为 VR 手柄 10.0.1.345（`e947fc358e9692358ac42cfe4a565c112f7fc9349da693643f863d08af98b3d2`）。固件地址为裸镜像偏移。下表描述可见应用镜像、APK 实现及既有实测；Boot ROM、板上其他芯片和完整 CC 总线报文不在样本内。

### 手机与线缆之间的 USB-PD 和 DP Alt Mode

| 消息 | 固件证据 | 解释 |
| --- | --- | --- |
| Discover Identity、Discover SVIDs | `0xB8B4` 起的身份对象含 VID 2109、PID 0105；`0xB8B0` 的 `00 00 01 FF` 被旧版 `0x414D`、新版 `0x4199` 读入缓冲区 | 声明 DisplayPort SVID `FF01`。Fold7 在原厂线和 Gen 2 直连下读到的 PD 对端身份分别为 `2109:0105` 和 `29cf:0001`。 |
| Discover Modes | 两版 `0xB8C4` 的 `05 0C 00 00`，构帧引用分别在 `0x41D3 / 0x421F` | 按插头的能力位图解码为 UFP_D、支持 pin C 与 D。 |
| DP Configure | 两版 `0x0380` 附近的命令 0x11 构帧引用 `0xB8E8` 的 `06 04 00 00` | 配置对象 `0x00000406` 指定 UFP_D、signalling=1、pin C。端口、执行分支及本次实际协商值仍需抓包对应。 |

两版 `0xB740–0xBFFD` 逐字节一致，包含上述模板；执行代码有差异。当前样本未给出带载时的供电合约、DP 训练结果、实时通道数或面板供电。CC 上传递的 DP 配置与后续 AUX 上的 DPCD 访问、链路训练属于不同观测点。[VDM 命令与身份字段](https://github.com/torvalds/linux/blob/v6.12/include/linux/usb/pd_vdo.h) · [DP 配置与 HPD 字段](https://github.com/torvalds/linux/blob/v6.12/include/linux/usb/typec_dp.h)

### USB Billboard、运行态 EP0 和 ROM 维护

Windows 单接线缆实读配置只有一个 Billboard 接口，无附加数据端点。两版应用镜像的常规 SETUP 分派表均位于 `0x18C8`。表内标准请求号为 `00/03/05/06/08/09/0A/0B`。五个其余分支如下；表外仍可能存在由硅内逻辑或 ROM 处理的请求。[实机描述符](../research/evidence/cable-c9496-diagnostics.json)

| bRequest | 处理入口 | 已核对的行为 |
| --- | --- | --- |
| A0 | 1F45 | 改动运行状态。04 号 APK 将其用于切换维护模式的流程。 |
| B0、C0 | 1F03、1F17 | 与重启和重新枚举有关。APK 和项目工具采用不同的模式切换序列。 |
| E0 | 1F50 | 子码 01/02 对应寄存器读写。地址由 wIndex 低字节及 wValue 高字节拼成；目前只掌握部分寄存器语义。 |
| E2 | 1F5D | 已定位的子码 01 返回头部四字节版本。04 号 APK 的 DEX 与 WinUSB 实测均对应 IN、wValue=1、wIndex=0、长度 4。 |

04 号包的 `CableUpgradingUtils`（混淆类 `m1.o`）通过 Android UsbManager 打开线缆接口 0。DEX 核对点为 `m1.o.k`，classes.dex 偏移 `0x28AAF0`。ROM 维护使用 EP0 至 SPI 桥，读状态 C2、读数据 C4、擦除 D2、发 SPI 指令 D4/D8、编程 DC。应用寻址映射到 `0x20000`，镜像区长 49,152 字节，按 4 KiB 扇区、32 字节写入和回读。维护桥的状态寄存器属于 Flash；其值不能解释为电池电量。[项目烧录实现](../tools/cable.py)

### 未解接口与不拆盒的验证边界

* 电池、充电 IC 和视频通道开关的板级连线及控制方式仍未知。已解析的常规 EP0 分派和原厂升级调用路径中，尚无带可核对单位的电池查询，也未识别外电旁路开关。通用寄存器入口本身不提供寄存器语义。
* `12d1:107e` 的 PCUI 串口和头显 HID 属于眼镜。头显报告 0x08 在两种线下均读取失败。另一个 VIA HID `2109:8888` 在 Gen 2 直连也存在。三者均不足以作为原厂线独有的控制面。正常出图的直连也对左右 LCDINFO 查询返回超时。
* 普通 PC USB 口适合验证 Billboard、版本和已知只读寄存器，不能从 EP0 直接观察 Fold7 在 CC 上交换的消息。可优先比较两种接法下手机 Type-C 控制器保留的 VDM 记录；若无原始记录，可在手机与线缆之间使用支持 DP Alt Mode 直通的 PD 分析仪。要确认主链路训练成功，还需源端训练日志或 AUX/DPCD 观测。

04 号包还有升级上报路径，型号字符串为 `C-CV10-Cable-C2C01`，`p1.q` 通过 HTTPS 提交 JSON；本轮仅检查代码。07 号华为 VR 服务的 DEX 在 `0x1D1AE8` 调用 `VRUtils.isCableDevice`，匹配线缆后退出普通头显插入流程。这解释了为何只跟踪 VR 服务的头显 JNI 会漏掉 04 号包内的线缆维护协议。

### 两版可复核的执行逻辑差异

比对相同分支的前置条件和共同尾部，可以排除单纯的地址平移。下表中的地址均为各自 8051 应用镜像的偏移。

| 位置 | C9.49.6 | C9.52.6 |
| --- | --- | --- |
| 状态分派中的附加条件 | 从 `0x5458` 附近检查内部 RAM `0x4D` 的 bit 4 和 `0x2E == 6`，在 `0x547B` 清位后继续 | 对应入口 `0x5427`。在 `0x544A` 清位后新增检查 `XDATA[0x2A5B] == 2`，满足时调用 `0x4BC2` |
| 新状态的影响 | `0x5485` 仅按一个标志位决定是否调用回调 | 新例程将内部间接 RAM `D2,D3` 分别置为 `03,E8`，并将当前 XDATA 状态写成 4。`0x545E` 增加状态 4 时跳过回调的分支 |
| 提前返回 | `0x259A` 的 `30 03 01 22` 在位地址 03 置位时返回 | 对齐后的 `0x25D2` 直接检查 `0x46 == 0x17` |

以上可确认新版修改了状态处理。两个字节组成的值为 1000，其计时单位与硬件事件未被标定。尚不能把它归为充电超时或 DP 修复。华为 04 号包的 `e1.d0` 同时使用 OTA 组件名 `com.huawei.vrhandle.c2c.firmware.6` 和产品名 `C-CV10-Cable-C2C01`。目前售后成功案例只有口述，未取得该线升级前后的版本或镜像。

### Fold7 上原厂线与直连的 DP 建链对照

2026-11-25 香港时间 22:08 的样本使用预充后接着 5 V 电源的原厂线，22:16 的样本使用 Gen 2 C-C 直连。手机内核记录两次都选中引脚配置 C，读到显示器 HUAWEIAV03，报告 bw_code=20、4 条通道，两阶段训练成功并启用视频流。两次都出现 HDCP 2.2 认证失败；直连时镜片可以显示测试图。两次从配置 C 到首次 HPD 高电平分别经过 8.239 秒、0.341 秒。这是两次连接的时序差异，因果关系仍待验证。完整系统诊断仅保留在本地。[两次连接的内核摘录](../research/evidence/fold7-original-vs-direct-dp.txt)

22:40 手机供电时，系统先移除两只华为设备，随后移除 VIA 2109:8888 和其父集线器 2109:2211。约 1.6 秒后父集线器重新枚举，再过约 0.8 秒 VIA 子设备出现；本次两只华为设备均未随之恢复。22:42 通过三星系统的 svc usb resetUsbPort 复测，复测后外屏仍在，USB 树仍只见集线器和 .5 子端口。由此可把控制路径的掉线定位到集线器级别，电源轨、电池及复位触发方仍未测定。[USB 接口事件时间线](../research/evidence/fold7-original-hub-reenumeration.txt)
